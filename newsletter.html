引子｜这一周可能是 AI 工具历史的转折点

如果你 4 月最后一周没刷 HN，那你大概错过了 AI 商业化历史上最像"图穷匕见"的一周：

  • 4 月 27 日：GitHub 宣布 Copilot 改成按用量计费（759 分上 HN）。同一天微软和 OpenAI 结束独家协议（975 分），结束了 ChatGPT 时代以来最大的婚姻。
  • 4 月 28 日：GitHub Copilot Code Review 也要消耗 GitHub Actions minutes（302 分），意味着每个 PR 的 AI 自动审查从此变成成本中心。
  • 4 月 29 日：HN 头条曝出 Anthropic 一个 bug——`HERMES.md` 在 commit message 里会被 Claude Code 重新读取并算作新 token 用量（991 分），用户合理 commit 习惯被 silently 计费。

三件事拼起来，一个判断浮出水面：AI 工具公司的"全包月"幻觉正在被撕掉。 接下来不是"再加个免费功能"的时代，是"每个动作都明码标价"的时代。

如果你还在用 fixed-price 订阅 + 不关心 token 流向，这一周你的成本结构已经被 silently 改写了——你只是还没收到对账单。

主线 #1｜AI 工具集体改计费：fixed price 时代结束

把这一周的几个数据点叠在一起看：

工具旧定价新定价时间
**GitHub Copilot**$10/月 全包按用量计费（每月免费额度 + 超出付费）2026-04-27 起
**Copilot Code Review**免费消耗 GitHub Actions minutes2026-06-01 起
**Anthropic Claude Code**Pro $20 fixed / Max $200 fixed仍 fixed，但**权重计算不透明**（HERMES.md bug 即此类）即时影响
**Cursor**$20 fixed仍 fixed，但 Q3 已 hint 会改待官宣

GitHub 官方 blog 措辞很直白："to better align cost with value delivered"——翻译："以前我们补贴重度用户，现在不补贴了。"

这不是 GitHub 一家的决定。AI 推理成本（GPU + 电费 + 模型托管）远高于 SaaS 时代的边际成本，fixed-price 模式只能在用户量 >> 重度用户时勉强维持。一旦重度用户占比超过临界点，公司就只能涨价或改计费模型。

GitHub 选了改计费。Anthropic 选了"fixed price + 隐性 throttle"（rate-limit 突然来 / token 计算口径不公开 / weekly limit 不透明）。两条路效果是一样的：让你为重度使用真实付费。

给已经在用的人：

  • 如果你日均 < 5 万 token：fixed-price 还划算
  • 如果你日均 > 30 万 token：你正在被新计费模式"再发现"，做好月成本翻 3-10 倍的准备
  • 如果你做"AI agent 后台跑"那种 high-throughput 用法：赶紧把热路径迁到本地或开源模型，否则下一波计费改革你会很疼

我自己的策略：把 Claude Code Pro 订阅留给"高质量低频"任务（写代码、改架构），把"低质量高频"任务（数据 scrape / 内容草稿生成 / 周报合成）迁到本地跑的开源 model（最近用 Qwen 2.5 32B 8-bit 在 RTX 3090 跑，prompt 质量降 30%，成本降 100%）。

主线 #2｜MSFT-OpenAI 分手：AI 巨头格局重组的开始

Bloomberg 4 月 27 日独家：微软和 OpenAI 结束 revenue-sharing 独家协议（HN 975 分，第 2 高）。

简单说：以前微软对 ChatGPT 的每笔收入抽成 + OpenAI 模型独家供给 Azure。现在两条都解除——OpenAI 模型可以上 AWS（4 月 28 日另一头条 #12 已确认 Bedrock 接 OpenAI），微软可以做自己的 frontier model（已在做，Phi 系列 + 收购 Inflection）。

中文圈的解读普遍偏地缘政治（"美国 AI 内斗"），但更准确的产业解读是：生态正在从"双寡头"转向"多极平台"。

短期影响：

  • 企业用户：如果你过去 18 个月 lock-in 在 Azure-OpenAI，现在多了 Bedrock-OpenAI 选项（同模型，可能不同价）
  • 创业者：以前选模型要先选 cloud，现在 model 和 cloud 解耦——你可以在 GCP 上跑 Anthropic + 在 Bedrock 上跑 OpenAI + 在自己服务器上跑 Llama，真正的多 vendor failover 时代来了
  • 投资人：OpenAI 的 moat 从"独家分发渠道"变成"模型本身"。如果 next-gen GPT 不能拉开 vs Anthropic / Gemini 的差距，估值会被重估

呼应同一周的另一条 HN 热门：#9 中国阻击 Meta 收购 Manus。两件事拼起来——东西方 AI 资产都在重新洗牌，"不可能合并"和"不再合作"几乎是同时发生。

给个人开发者的实操：现在比任何时候都该用 LiteLLM / OpenRouter 这类模型路由层。以后你的 Claude 用量飙了，能 1 行代码切到 OpenAI o4 或 Gemini 3 上备用。模型 vendor lock-in 是未来 12 个月最大的隐性成本。

主线 #3｜开源社区的反扑：一周 3 个绕开 Claude Code 的工具登上 GitHub trending

在 Anthropic 用 HERMES.md bug + rate-limit + 不透明计费"教育"用户的同一周，GitHub Python / TypeScript trending 同时挤进了 3 个工具，全部冲着 Claude Code 来：

仓Stars (本周新增)卖点
**`Alishahryar1/free-claude-code`**18,598"Use claude-code for free in terminal / VSCode / Discord" — 用 OpenClaw（开源代理）替换 Anthropic backend
**`zilliztech/claude-context`**10,300Code search MCP for Claude Code，让整个代码库变成 context
**`mksglu/context-mode`**11,242"98% context reduction" sandbox，14 平台支持

这是开源社区的典型应激反应：当商业工具开始 squeeze 用户，开源替代方案 24 小时内冒出来 + 一周内积累几万 star。

但先别 over-celebrate。free-claude-code 这种工具的本质是 license-bypass——它依赖 reverse-engineer Claude API endpoints + 用 third-party proxy。Anthropic 完全可以下周用一个鉴权改动把它废掉。短期收益高，长期 fragile。

真正长期 robust 的方向是另两个：

  • `claude-context` 的 MCP 模式——遵守官方协议、扩展能力，不绕过计费。Anthropic 反而欢迎。
  • `context-mode` 的 token 压缩——直接降你的 API 用量。是 saving 不是 stealing。

如果你真的想"少花钱"，学 MCP 写自己的工具 > 装 free-claude-code。前者让你长期成本下降 50%+，后者下个月可能就死。

个人化 takeaway｜你这周该做什么

如果你已经用 Claude Code / Copilot / Cursor 之一且重度使用，这一周的信号叠在一起是非常清晰的：

1. 做一次自己的 token audit

打开你的 Anthropic / OpenAI dashboard，看过去 30 天每天的真实 token 消耗。如果接近 plan 上限，2026 下半年涨价波及到你的概率 > 80%。

2. 把"高频低质量"任务搬走

草稿生成、数据 scrape、内容翻译、单元测试样板代码——这些任务用 Qwen / Llama / Mistral 本地跑足够，没必要烧 frontier model token。

3. 学一个 MCP 写法

未来 12 个月，能熟练写 MCP server 的人 = 能扩展 Claude/Cursor 能力的人 = 能在 fixed-price plan 内做更多事的人。Anthropic 官方文档 1 小时看完。

4. 准备多 vendor failover

用 LiteLLM 或 OpenRouter 在你的关键 agent 流程里做模型 fallback。Claude 挂了切 GPT-4o，GPT 挂了切 Gemini 3。单 vendor 依赖是 2026 下半年最危险的架构假设。

5. 最重要——别被 fixed-price 错觉养成大手大脚

fixed-price 让你以为 AI 是免费的，但供给侧的真实成本一直在那里。当计费模型改变时，只有把"成本"放心智模型里的人能 survive。
